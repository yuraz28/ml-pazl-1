# Занятие 20. Кортежи и множества

## Цель занятия

Познакомиться с двумя «родственниками» списка: кортежем – списком, который нельзя изменить, и множеством – коллекцией без повторов и без порядка. Понять, когда какой из четырёх типов коллекций нужен, и решить задачи, где кортежи и множества реально экономят код: удаление дублей и поиск общих элементов.

---

## Теория

### Четыре способа хранить набор данных

К этому занятию у нас есть строка и список. Оба – последовательности: элементы лежат по порядку, у каждого есть индекс. Но в жизни встречаются данные другого вида.

- `'Аня'` – одно значение. Строка, если это текст.
- `['Аня', 'Марк', 'Лиза']` – набор по порядку, элементы можно менять. Список.
- `(3, 5)` – пара чисел, которая не должна меняться. Для этого есть кортеж.
- `{'Аня', 'Марк', 'Лиза'}` – набор без повторов, где важен сам факт «кто есть», а не порядок. Для этого есть множество.

Разница не в записи, а в том, какие операции разрешены. Дальше – по порядку.

### Кортеж: список, который нельзя изменить

Кортеж записывают в круглых скобках:

```python
point = (3, 5)
print(point[0], point[1])    # 3 5
print(len(point))            # 2
print(5 in point)            # True
```

Всё, что мы умеем делать со списком «на чтение», работает и здесь: индексы, срезы, `len`, `in`, перебор в цикле `for`.

```python
point = (3, 5)
print(point[0])      # 3
print(point[-1])     # 5
print(point[0:2])    # (3, 5)
```

А изменить нельзя:

```python
point = (3, 5)
point[0] = 7
# TypeError: 'tuple' object does not support item assignment
```

Ошибка не случайная, а смысловая: кортеж создан для данных, которые не должны меняться. Координаты, размеры окна, цвет в формате `(255, 255, 255)`, название и автор книги – всё это «снимки», которые незачем править на месте.

Две детали записи, с которыми путаются чаще всего:

```python
point = 3, 5          # скобки можно не писать, это тот же кортеж
print(type(point))    # <class 'tuple'>

one = (5,)            # кортеж из одного элемента - запятая обязательна
print(type(one))      # <class 'tuple'>

not_tuple = (5)       # а это просто число в скобках
print(type(not_tuple))  # <class 'int'>
```

Скобки в Python часто означают «сначала посчитать внутри». Кортеж делает кортежем не скобка, а запятая.

### Где кортежи реально нужны: несколько значений из функции

На занятии 13 функция возвращала одно значение. Но что, если нужно вернуть два – например, минимум и максимум?

```python
def min_max(numbers):
    return min(numbers), max(numbers)


result = min_max([4, 9, 2, 7])
print(result)          # (2, 9)
print(type(result))    # <class 'tuple'>
```

`return a, b` собирает значения в кортеж. Дальше его удобно **распаковать** – разложить по переменным:

```python
low, high = min_max([4, 9, 2, 7])
print(low)     # 2
print(high)    # 9
```

Количество переменных слева должно совпадать с количеством значений справа, иначе будет `ValueError`.

Распаковка пригодится и в бытовой задаче – поменять значения местами без третьей переменной:

```python
x = 1
y = 2

x, y = y, x
print(x, y)    # 2 1
```

Справа сначала собирается кортеж `(2, 1)`, потом он раскладывается по переменным. В других языках для обмена нужна промежуточная переменная, здесь – одна строка.

### Множество: коллекция без повторов

Множество записывают в фигурных скобках:

```python
letters = {'м', 'о', 'л', 'о', 'к', 'о'}
print(letters)    # {'м', 'о', 'л', 'к'} - порядок может быть другим
```

Повторы исчезли сами. Это главное свойство: **в множестве каждый элемент встречается один раз**.

Создать множество можно и из другой коллекции:

```python
print(set('молоко'))                        # {'м', 'о', 'л', 'к'}
print(set([3, 5, 3, 7, 5, 3]))              # {3, 5, 7}
empty = set()                               # пустое множество
print(type(empty))                          # <class 'set'>
```

`set()` из строки берёт отдельные символы, из списка – его элементы. Пустое множество создают только через `set()`: пара фигурных скобок `{}` означает словарь, с ним познакомимся на следующем занятии.

Три важных ограничения:

- **Порядка нет.** Не «элементы перемешались», а самого понятия «первый элемент» не существует. Порядок вывода может отличаться от запуска к запуску – это нормально, не баг.
- **Индексов нет.** `letters[0]` выдаст `TypeError: 'set' object is not subscriptable`. Взять «первый» элемент нельзя, потому что «первого» нет.
- **Элементы уникальны.** Добавили то, что уже есть, – ничего не произошло, ошибки не будет.

Проверим вывод два раза подряд:

```python
print(set(['яблоко', 'банан', 'киви', 'груша']))
# {'груша', 'киви', 'яблоко', 'банан'}
# {'киви', 'груша', 'банан', 'яблоко'} - во втором запуске порядок другой
```

Поэтому множества печатают для проверки, а не для красивого вывода. Если нужен стабильный порядок – сортируют перед печатью или используют список.

### Операции над множествами

Основные действия:

| Операция | Запись | Что получается |
| :---- | :---- | :---- |
| Добавить элемент | `s.add(x)` | Множество с новым элементом |
| Удалить элемент | `s.remove(x)` | Без `x`; если его нет – ошибка `KeyError` |
| Удалить без ошибки | `s.discard(x)` | Без `x`; если его нет – ничего не произойдёт |
| Проверить наличие | `x in s` | `True` или `False`, работает мгновенно |
| Сколько элементов | `len(s)` | Число уникальных элементов |
| Объединение | `a.union(b)` | Всё, что есть хотя бы в одном |
| Пересечение | `a.intersection(b)` | Только общее для обоих |
| Разность | `a.difference(b)` | Что есть в `a`, но нет в `b` |

У трёх последних операций есть короткая запись знаками: `a | b`, `a & b`, `a - b`. Знак `|` внутри таблицы печатать неудобно – он ломает разметку, поэтому в таблице указаны методы.

Проверим на двух списках покупок:

```python
a = ['яблоко', 'банан', 'киви', 'груша']
b = ['киви', 'груша', 'слива']

print('Общие:', set(a) & set(b))          # {'киви', 'груша'}
print('Только у меня:', set(a) - set(b))  # {'яблоко', 'банан'}
print('Всё вместе:', set(a) | set(b))     # пять фруктов
```

`&` и `|` читаются как «и» и «или»: пересечение – то, что подходит под оба условия, объединение – под хотя бы одно. Те же знаки, что в логических операторах из занятия 7, и смысл похожий.

Перебрать множество можно обычным `for`:

```python
for letter in {'м', 'о', 'л', 'к'}:
    print(letter)
```

Порядок обхода при этом не гарантирован.

### Какой тип когда брать

| Нужно | Тип | Пример |
| :---- | :---- | :---- |
| Менять элементы, важен порядок | Список | Список задач, поле игры |
| Данные-«снимок», менять нельзя | Кортеж | Координаты, пара «минимум и максимум» |
| Убрать повторы, искать общее | Множество | Уникальные слова, общие друзья |
| Хранить пары «ключ → значение» | Словарь | Телефонная книга (занятие 21) |

### Задача 1. Убрать дубли из списка

Дан список чисел с повторами. Нужно оставить каждое число по одному разу.

Самый короткий путь – превратить список в множество и обратно:

```python
numbers = [3, 5, 3, 7, 5, 3]

print(set(numbers))          # {3, 5, 7}
print(list(set(numbers)))    # [3, 5, 7]
```

Работает, но есть подвох: **порядок теряется**. Для чисел это незаметно, а для списка имён или городов результат будет в случайном порядке.

Если порядок важен, идём по списку и добавляем только то, чего ещё не было. Проверять будем по множеству: `x in set` отвечает мгновенно, в отличие от `x in list`, который перебирает элементы.

```python
numbers = [3, 5, 3, 7, 5, 3]

unique = []
seen = set()

for x in numbers:
    if x not in seen:
        unique.append(x)
        seen.add(x)

print(unique)    # [3, 5, 7] - порядок первого появления сохранён
```

Здесь два контейнера с разными задачами: `unique` – результат в нужном порядке, `seen` – быстрая проверка «уже было?». Такой приём встречается в реальном коде постоянно.

### Задача 2. Что есть в обоих списках

У двух ребят есть списки фильмов, которые они хотят посмотреть. Нужно найти общие.

```python
mine = ['Интерстеллар', 'Начало', 'Дюна', 'Матрица']
friend = ['Дюна', 'Матрица', 'Гравитация']

common = set(mine) & set(friend)
print('Посмотрим вместе:', common)
print('Сколько общих:', len(common))
```

Проверьте сами, что получится из `set(friend) - set(mine)` и `set(mine) | set(friend)`.

### Задача 4. Сколько разных букв в слове

```python
word = 'молоко'
letters = set(word)

print(letters)               # {'м', 'о', 'л', 'к'}
print('Разных букв:', len(letters))
print('Буква о есть:', 'о' in letters)
```

По этому же принципу решается проверка «есть ли в слове повторяющиеся буквы»: если `len(set(word)) < len(word)`, значит, какая-то буква встречается больше одного раза. Сравните с тем, как та же проверка выглядела бы на списках.

### Частые ошибки

- `point[0] = 7` для кортежа – `TypeError`. Кортеж не меняется: нужен новый кортеж или список.
- `one = (5)` вместо `one = (5,)` – получается число, а не кортеж из одного элемента.
- `s = {}` вместо `s = set()` – создаётся словарь, а не пустое множество.
- `letters[0]` – у множества нет индексов. Нужен `list(letters)[0]` (порядок при этом случайный) или перебор в цикле.
- `s.remove(x)` для отсутствующего элемента – `KeyError`. Если непонятно, есть элемент или нет, – `discard`.
- Ожидание порядка при печати множества. Разный порядок в двух запусках – нормальное поведение.
- `list(set(numbers))` там, где порядок важен. Дубли уйдут, но порядок потеряется – нужен вариант с `seen`.
- `a & b` для списков – `TypeError`. Операции множеств работают только с множествами, сначала `set(a)`.

## Итоги

- Кортеж – неизменяемая последовательность. Индексы, срезы, `len`, `in` и перебор работают так же, как у списка, но изменить элемент нельзя.
- Кортеж из одного элемента требует запятой: `(5,)`. Скобки необязательны, `3, 5` – тоже кортеж.
- `return a, b` возвращает кортеж, а `low, high = ...` его распаковывает. Так из функции отдают несколько значений и меняют переменные местами.
- Множество хранит уникальные элементы без порядка и без индексов. Создаётся через `{...}` или `set(...)`, пустое – только через `set()`.
- Операции `&`, `|`, `-` дают общее, объединение и разность. Проверка `x in set` работает мгновенно, поэтому множества берут для поиска дублей и общих элементов.
- Порядок элементов множества не гарантирован: печатать его «для красоты» нельзя, а для сохранения порядка нужен список с отдельным множеством `seen`.
