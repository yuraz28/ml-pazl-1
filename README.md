# О репозитории

Репозиторий преподавателей для первого курса пазла. Направление ML.
Здесь хранятся презентации и домашние задания. Если вы нашли ошибку, то срочно сообщайте!

# Как сообщить об ошибке

1. **Сделать PR** — если вы готовы предложить исправление самостоятельно.
2. Юра смотрит PR.
3. Если всё в порядке — вливает изменения.
4. После этого **обязательно напишите в чат**, чтобы все стянули обновлённый вариант уроков.

> ⚠️ Важно: не забудьте предупредить остальных в чате после того, как правки были влиты. Иначе у многих останутся старые версии материалов.

## Установка окружения

Для работы с репозиторием мы используем пакетный менеджер [uv](https://docs.astral.sh/uv/). Он сам управляет версиями Python, зависимостями и виртуальным окружением.

### 1. Установка `uv`

**Linux / macOS:**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows (PowerShell):**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

После установки перезапустите терминал (или выполните `source $HOME/.local/bin/env` на Linux/macOS) и проверьте, что команда доступна:

```bash
uv --version
```

### 2. Создание виртуального окружения

```bash
uv sync
```

`uv sync` установит все зависимости из `pyproject.toml` / `uv.lock` в `.venv`.

> 💡 Если команда `uv run ...` не находит `.venv`, убедитесь, что вы находитесь в корне репозитория (там, где лежит `pyproject.toml`).

## Страница занятий и `config.yaml`

`index.html` в корне — страница со списком занятий. Данные для неё (название, число
слайдов, дата открытия) лежат в JSON-блоке внутри самого файла и собираются скриптом
`scripts/build_lesson_index.py` из папок `classes/<NN>-lessons/`.

В карточке занятия снизу — две кнопки:

- **«Презентация»** — открывает деку, путь берётся из поля `presentation`;
- **«Описание»** — открывает страницу, собранную из markdown-файла, путь из поля `docs`.

У закрытого занятия (когда дата `opens` ещё не наступила) обе кнопки неактивны, а справа
сверху на карточке показана только дата выхода, например «12 октября»; если дата не задана
или указано `soon` — «Soon...». Обратного отсчёта нет.

Кнопок может быть и одна: у занятия бывает только дека, только описание или оба. Если поля
`presentation` нет — кнопки «Презентация» не будет (см. правило ниже).

Что не удаётся снять с деки — расписание и ссылки — задаётся в общем `config.yaml` в корне:

```yaml
course:
  title: "Все занятия курса"
  branch: main

lessons:
  - n: 13
    title: "Функции"
    opens: 2026-10-05                 # дата прошла → занятие открыто
    presentation: classes/13-lessons/13-funkcii.html
    docs: classes/13-lessons/13-text.md
  - n: 14
    opens: 2026-10-12                 # дата впереди → карточка закрыта, в углу «12 октября»
```

Конфиг сейчас заполнен на все 45 занятий: дата прошла → занятие открыто (как только
есть материалы), дата впереди → карточка закрыта и показывает дату выхода.

Поля урока: `n` (номер), `title`, `opens` (`YYYY-MM-DD` или `soon`),
`presentation` (путь до деки), `docs` (путь до описания в markdown). Занятие без `opens`
считается открытым сразу, как появятся материалы.

**Если занятие указано в `config.yaml`, ссылки берутся только оттуда.** Убрали у занятия
`presentation` — кнопки «Презентация» у него не будет, даже когда в папке занятия лежит
подходящий `.html`: пересборка не вернёт удалённое поле. То же и с `docs`. Для занятий,
которых в конфиге нет, дека по-прежнему подхватывается из папки автоматически. Если у
описанного в конфиге занятия дека в папке есть, а `presentation` не указан, сборщик пишет
об этом в выводе — чтобы пропажа не была неожиданной.

### Описания в markdown

Описание ведём в `.md` (например, `classes/13-lessons/13-text.md`) — так его удобно
редактировать и читать на GitHub. Чтобы браузер показал его красиво, при сборке markdown
превращается в готовую страницу `docs/lesson-NN.html` (та же стилистика сайта: заголовки,
таблицы, списки, код). Кнопка «Описание» ведёт именно на эту страницу.

Для этого нужен пакет `markdown` (он указан в `pyproject.toml` и ставится через `uv sync`).

Блоки кода пишем как обычно — тремя обратными кавычками, и их можно ставить с отступом
внутри списка (как на GitHub):

    ```python
    print("Hello World")
    ```

Сборщик сам превращает такой блок в код на странице — отступ не мешает.

Если пакета нет, сборка не падает — описание соберётся как простой текст с предупреждением.

Страница статична и публикуется на GitHub Pages: **открыто занятие или нет, решает
сам браузер** — сравнивает `opens` с текущей датой при загрузке. Никакого сервера для
этого не нужно. Это отсечка для удобства, а не защита: файл деки лежит в репозитории
и при желании открывается напрямую.

### Служебная страница «/metod»

Для проверки материалов есть служебная страница `/metod` (файл `metod/index.html`) — та же
витрина, но **все занятия открыты**, независимо от даты в `opens`. Ссылки на презентации и
описания ведут туда же, куда и с обычной страницы.

Страница нигде не проставлена ссылкой и помечена `noindex`, но это не защита: файл лежит в
репозитории, и `/metod` открыт любому, кто знает адрес. Собирается автоматически из
`index.html` тем же скриптом — руками её править не нужно.

Пересобрать оглавление вручную после правки конфига:

```bash
uv run python scripts/build_lesson_index.py
```

На GitHub это делает workflow «Оглавление занятий» автоматически при пуше в `main`
(срабатывает на изменения `config.yaml`, `classes/**/*.html`, `classes/**/*.md`
и самого скрипта).
