Занятие 24. JSON файлы

Цель занятия

Познакомиться с форматом JSON и научиться сохранять в него сложные структуры данных – словари со списками внутри. Разобрать соответствие типов Python и JSON, методы json.load и json.dump. Оформить результаты прошлого занятия в отчёт JSON.

Теория

Зачем ещё один формат

На занятии 23 мы работали с CSV – плоской таблицей. Для оценок этого хватало: строка на ученика, столбцы на предметы. Но данные часто устроены глубже.

У ученика несколько предметов, у каждого предмета несколько оценок с датами, у класса есть название и учебный год. При этом учеников в классе разное количество, а предметы у разных учеников могут отличаться. В плоскую таблицу такое не влезает: понадобятся пустые клетки, дополнительные файлы и договорённости.

JSON – JavaScript Object Notation – текстовый формат для данных с вложенностью. Главное удобство: он записывается почти так же, как выглядят словари и списки Python. То есть структуру, которую вы придумали в коде, можно сохранить в файл как есть и потом прочитать обратно.

Как выглядят данные в JSON

{
  "class": "10 А",
  "students": [
    {"name": "Аня", "marks": {"математика": 5, "русский": 4}},
    {"name": "Марк", "marks": {"математика": 4, "русский": 4}}
  ]
}

Фигурные скобки – объект, квадратные – массив. Внутри объекта пары «ключ: значение», ключ всегда в двойных кавычках. Внутри массива – значения по порядку. Структуры вкладываются друг в друга на любую глубину.

Соответствие типов:

Python JSON Пример
dict объект {...} {"name": "Аня"}
list массив [...] [1, 2, 3]
str строка "..." "привет"
int, float число 5, 4.67
True / False true / false true
None null null

Проверить превращение можно без файлов – методами dumps и loads (буква s – от string, «строка»):

import json

print(json.dumps([True, False, None, 5]))
# [true, false, null, 5]

print(json.dumps('привет'))
# "\u043f\u0440\u0438\u0432\u0435\u0442"

Вторая строка показывает важную деталь: по умолчанию русские буквы превращаются в коды \u.... Файл остаётся корректным, но читать его глазами невозможно. Лечится параметром ensure_ascii=False.

import json

print(json.dumps('привет', ensure_ascii=False))
# "привет"

Запись в файл: json.dump

import json

phonebook = {'Аня': '+7 900 111-22-33', 'Марк': '+7 900 444-55-66'}

with open('phonebook.json', 'w', encoding='utf-8') as f:
    json.dump(phonebook, f, ensure_ascii=False, indent=2)

Файл открывается как обычный текстовый (занятие 22): режим 'w', кодировка utf-8. Только пишет в него не f.write, а json.dump.

Параметры, которые стоит указывать всегда:

  • ensure_ascii=False – русские буквы остаются буквами.
  • indent=2 – отступ в два пробела на каждый уровень вложенности. Без него файл запишется одной длинной строкой: программа прочитает, а человек – нет.

Порядок аргументов: сначала что записываем, потом куда.

Чтение из файла: json.load

import json

with open('phonebook.json', 'r', encoding='utf-8') as f:
    data = json.load(f)

print(data)
print(type(data))    # <class 'dict'>

json.load возвращает готовую структуру Python: объект станет словарём, массив – списком, числа – числами. Никаких int() и ручного разбора, в отличие от CSV. Это главное удобство JSON.

Если в файле массив верхнего уровня, получится список:

with open('books.json', 'r', encoding='utf-8') as f:
    books = json.load(f)      # список словарей

Отличие от CSV и от текстового файла

txt csv json
Структура никакой, просто текст таблица любая вложенность
Типы всё строки всё строки сохраняются
Где применяют заметки, логи, отчёты таблицы, выгрузки конфиги, приложения, API

Три ограничения JSON, о которые спотыкаются:

  • Ключи только строки. Числовые ключи при записи станут строками, и после чтения словарь будет с другими ключами.
  • Кортеж станет списком. (3, 5) запишется как [3, 5] и вернётся списком – JSON не знает неизменяемых последовательностей.
  • Комментариев нет. В JSON нельзя оставить пояснение в файле, как в коде.

Плюс формат строгий: одинарные кавычки, лишняя запятая в конце или «умные» кавычки из Word ломают файл. Об этом – ошибка JSONDecodeError.

Где вы это увидите

  • Файлы настроек приложений и игр.
  • Сохранения прогресса.
  • Ответы серверов при работе с API – занятие 26. Тогда json.loads будет разбирать не файл, а строку с ответом.

Практика

Задача. Дневник класса в JSON

Берём данные прошлого занятия (оценки класса) и оформляем их в JSON так, как это делают настоящие приложения: класс, дата, список учеников, у каждого – словарь оценок.

Шаг 1. Собрать структуру в Python

import json

gradebook = {
    'class': '10 А',
    'date': '2026-12-21',
    'students': [
        {'name': 'Аня', 'marks': {'математика': 5, 'русский': 4, 'информатика': 5}},
        {'name': 'Марк', 'marks': {'математика': 4, 'русский': 4, 'информатика': 3}},
        {'name': 'Лиза', 'marks': {'математика': 5, 'русский': 5, 'информатика': 5}},
    ],
}

Разберитесь, что здесь во что вложено: словарь → список students → словари учеников → словарь marks → числа. Именно такую «матрёшку» плоская таблица не сохранит.

Программа – lesson24.py в папке занятия.

Шаг 2. Записать в файл

with open('gradebook.json', 'w', encoding='utf-8') as f:
    json.dump(gradebook, f, ensure_ascii=False, indent=2)

print('Сохранено')

Откройте gradebook.json в VS Code. Должно быть читаемо: отступы, русские буквы, числа без кавычек. Если увидели \u043f... – забыли ensure_ascii=False. Если всё в одной строке – забыли indent=2.

Шаг 3. Прочитать обратно

with open('gradebook.json', 'r', encoding='utf-8') as f:
    data = json.load(f)

print('Файл прочитан заново:', type(data))
print('Класс:', data['class'])
print('Первый ученик:', data['students'][0]['name'])
print('Его математика:', data['students'][0]['marks']['математика'])

Смысл шага: убедиться, что из файла вернулась та же структура. type(data) покажет dict, а не строку. Доступ к глубокому значению – цепочка индексов, как в занятии 21.

Шаг 4. Посчитать и сохранить отчёт

report = {'class': data['class'], 'students': []}

for student in data['students']:
    total = 0
    for mark in student['marks'].values():
        total += mark
    average = total / len(student['marks'])
    report['students'].append({'name': student['name'], 'average': round(average, 2)})
    print(student['name'], '-', round(average, 2))

with open('gradebook_report.json', 'w', encoding='utf-8') as f:
    json.dump(report, f, ensure_ascii=False, indent=2)

values() здесь удобнее items(): нужны только оценки, а не названия предметов. Новый отчёт собираем с нуля – так структура получается чище, без лишних полей исходника.

Результат:

Аня - 4.67
Марк - 3.67
Лиза - 5.0

А в gradebook_report.json:

{
  "class": "10 А",
  "students": [
    {"name": "Аня", "average": 4.67},
    {"name": "Марк", "average": 3.67},
    {"name": "Лиза", "average": 5.0}
  ]
}

Шаг 5. Доработки на выбор

  • Добавить в отчёт «лучший предмет» каждого ученика и средний балл по классу.
  • Добавить поле read типа True/False (например, «четверть закрыта») и проверить, что в файле оно станет true.
  • Сохранить в JSON сразу два класса: {'classes': [ {...}, {...} ]}.
  • Сравнить размер gradebook.json и старого marks_report.csv. Сделать вывод, где хранить удобнее.
  • Сломать файл руками (убрать запятую) и посмотреть на JSONDecodeError – чтобы узнать ошибку в лицо.

Частые ошибки

  • f.write(gradebook) – TypeError. Словарь записывают через json.dump, а write принимает только строку.
  • json.dump(gradebook, f) без ensure_ascii=False – в файле \u0430\u043d\u044f.
  • Без indent=2 – весь JSON в одну строку, глазами не проверить.
  • json.loads(f) вместо json.load(f) – loads работает со строкой, а не с файлом; будет TypeError.
  • JSONDecodeError: Expecting ',' delimiter – в файле сломана разметка: пропущена запятая, одинарные кавычки, лишняя запятая перед закрывающей скобкой.
  • KeyError при data['students'] – файл прочитался, но структура другая (например, верхний уровень – список).
  • Числовые ключи словаря после сохранения и чтения стали строками: {1: 'а'} превратится в {'1': 'а'}.
  • Открыли файл в режиме 'w', чтобы «посмотреть», – данные стёрлись. Для чтения только 'r'.

Итоги

  • JSON – текстовый формат для данных с вложенностью. Объекты {} соответствуют словарям, массивы [] – спискам.
  • Типы в JSON сохраняются: числа остаются числами, true/false – логическими значениями, null – это None. Преобразовывать ничего не нужно.
  • json.dump(объект, f, ensure_ascii=False, indent=2) записывает в файл, json.load(f) читает и возвращает словарь или список.
  • dumps/loads работают со строкой вместо файла – пригодятся, когда данные приходят от сервера.
  • Русские буквы в файле появляются только с ensure_ascii=False, читаемая структура – с indent=2.
  • Ограничения: ключи только строки, кортежи становятся списками, комментариев нет, формат строгий – одна лишняя запятая даёт JSONDecodeError.
